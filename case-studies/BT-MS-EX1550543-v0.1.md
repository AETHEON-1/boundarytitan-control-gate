## Purpose and bounded scope
Investigate whether health detection, automated remediation, capacity eviction and load redistribution can compose into a positive-feedback failure mode without an effective independently enforced bound. Microsoft 365 incident EX1550543 is the motivating case, not proof of the proposed feedback loop. No Microsoft access, credentials, production probes or exploit attempts are within scope.

## Claim separation (51-50)
Documented within reviewed materials: incident advisory identifier EX1550543; user-visible public discussion of Exchange Online access problems; existing BoundaryTitan repository control questions.
Bounded inference: health-check-triggered eviction and load redistribution could produce a positive feedback loop in a distributed system; independently enforced limits could reduce correlated capacity loss in some designs.
Open: incident root cause; whether eviction decisions were recursive; whether mitigations were preventive or emergency-only; which control plane owned removal; whether any independent stop path existed and was effective; whether malicious activity caused or contributed to the incident; whether suggested controls would have prevented the actual incident.
Do not equate public attack rumors with forensic attribution or a vendor denial with comprehensive independent exoneration.

## Mechanism under test
Health observation -> failure classification -> proposed remediation -> authorization/constraint check -> capacity eviction or restart -> workload redistribution -> measured effect -> possible new health observations.
First unsupported arrow: failure classification -> permission for consequential remediation at potentially correlated scale.
Alternative causal models: common-mode software defect; external traffic shock; resource exhaustion without eviction feedback; faulty configuration rollout; upstream dependency; malicious interference (unestablished); a mixture of these.

## Sigma-2 question
Does the health-control plane enforce an independently effective upper bound on correlated capacity eviction, including during partitions, stale telemetry, recovery and controller compromise, or can remediation decisions amplify a local fault into systemic unavailability?

## Proposed synthetic test (DESIGN ONLY; NOT EXECUTED)
Environment: isolated local deterministic simulation with synthetic nodes, synthetic traffic, no network, credentials, cloud access, third-party systems, production data or uncontrolled child processes.
Controlled variables: correlated health-check false-positive rate; workload arrival; available capacity; eviction threshold; retry budget; hysteresis; isolation domain; control-plane availability; stale telemetry; delayed recovery.
Comparators: A = unconstrained reactive eviction policy; B = bounded eviction with minimum viable capacity, per-domain limits, cooldown/hysteresis and explicit independent halt control.
Outcomes: cumulative capacity evicted, peak utilization, service availability, time to recovery, attempted/denied remediations, false-negative halt outcomes, stop latency and whether any alternative consequential path bypasses the gate.
Adversarial cases: correlated false positives; delayed telemetry; retry storms; partial partition; controller restart; queued actions after revocation; bypass of proposed halt; conflicting recovery histories; independent monitor unavailable.

## Evidence required for a meaningful result
Pinned simulator code and scenario specification; exact version/configuration and hashes; run identity; raw event log; independent effect observer; independently retained stop-command and observed-stop receipts; coverage statement; original failures; alternative explanations; negative tests; reviewer identity and disposition.
A passing simulation demonstrates only behavior within its model and coverage, not Microsoft root cause or production safety.

## Minimum falsifiers
F1. An eviction proceeds beyond the specified capacity bound while the bound is claimed to be enforced.
F2. A remediation action executes after the defined external stop cutoff through queue, restart or alternate controller path.
F3. The controller and its observer jointly report a successful stop while the independently observed effect continues.
F4. A system with bounded controls still collapses under the same synthetic assumptions, contradicting the proposed sufficiency claim.
F5. The observed Microsoft incident mechanism is explained without eviction feedback, invalidating its use as evidence of that specific mechanism (without invalidating the generic test question).

## Omissions and inverse/converse checks
A server becoming unavailable does not establish health-check eviction as its cause. Eviction does not entail that remaining nodes overloaded. Recovery instability does not entail recursive remediation. An external circuit breaker does not guarantee availability; it may preserve harmful capacity or block necessary repair. Independent administration does not automatically establish causal, evidentiary or authority independence. A human approval click is not necessarily an independent brake. No malicious attribution follows from the outage. No vendor innocence follows solely from the absence of a public attack indicator.
