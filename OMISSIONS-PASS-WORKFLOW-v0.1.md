# Omissions Pass Workflow v0.1

## Sequence

`Declare surface → Inspect coverage → Check evidence → Check assumptions → Check owner → Check authority → Check stop → Check consequence → Check affected party → Check reversibility → Check time → Check appeal → Check dependencies → Check accessibility → Check ledger → Route specialist`

The pass treats absence as a finding. It does not infer that an owner, stop path, appeal route, measurement, or evidence record exists merely because the architecture expects one.

## Output

Each finding includes:

- category
- severity
- missing element
- review question
- rejection condition

## Boundary

`NO_OMISSIONS_IN_SUPPLIED_SURFACES` means only that the declared fields were supplied for the supplied surfaces. It does not mean the surfaces are safe, lawful, complete, independently verified, or approved.

The workflow cannot authorize, certify, deploy, or close itself.
