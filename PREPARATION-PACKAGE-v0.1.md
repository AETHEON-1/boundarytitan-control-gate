# BoundaryTitan Control Gate — Preparation Package v0.1

**State:** PREPARATION READY / IMPLEMENTATION NOT AUTHORIZED
**Purpose:** convert the repository’s strongest boundary concepts into reviewable implementation packets without silently promoting them into live authority.

## Preparation boundary

The repository may prepare contracts, fixtures, test plans, schemas, review packets, and evidence requirements.

Preparation does not authorize:

- live credentials
- live-system inspection
- permission grant or revocation
- robot control
- deployment
- safety certification
- publication
- closure of unresolved review

## Priority build packets

### P1 — Ledger spine

Prepare an append-only event contract for proposals, holds, denials, handoffs, revocations, corrections, reopenings, and human dispositions.

Required evidence:

- event ordering rule
- immutable prior-record preservation
- correction-record semantics
- hash or custody strategy
- replay reconstruction test

Human review required: evidence owner and repository owner.

### P2 — External brake test harness

Prepare adversarial tests for brake independence, planner failure, communication loss, stale state, queued action, restart, and revocation delay.

Required evidence:

- independent trigger path
- measured stop latency
- maximum harm window
- stop-path owner
- failure-state behavior
- external test witness

Human review required: robotics safety specialist, controls specialist, site authority.

### P3 — Authority actuality checker

Prepare a contract that distinguishes a named owner from an owner with actual authority to deny, revoke, isolate, or stop before consequence.

Required evidence:

- authority basis
- scope
- effective period
- reachable denial path
- revocation path
- conflict handling
- timing against consequence window

Human review required: consequence owner and governance/legal specialist where applicable.

### P4 — Temporal and revocation harness

Prepare deterministic tests for expiry, clock skew, delayed revocation, cached access, delegated access, queued actions, retries, restart, and time-of-check/time-of-use races.

Required evidence:

- declared timing bounds
- enforcement observation point
- revocation-to-enforcement measurement
- fail-closed behavior
- recovery behavior when fail-closed blocks legitimate work

Human review required: controls or security specialist.

### P5 — Specialist handoff protocol

Extend the current handoff battery into a disposition loop with specialist response, dissent, rejection, narrowing, reopening, and human decision records.

Required evidence:

- recipient role
- failed-test custody
- open-question ownership
- rejection condition
- specialist disposition
- unresolved uncertainty
- explicit remaining stop authority

Human review required: named specialist recipient and consequence owner.

### P6 — 51-50 omission compiler

Prepare a reusable scanner that classifies claims as documented record, bounded inference, or open question and identifies the first unsupported arrow.

Required evidence:

- source reference
- claim identifier
- evidence state
- unsupported transition
- missing owner
- missing stop path
- consequence if wrong

Human review required: domain owner for each routed lane.

## Preparation acceptance gates

No packet advances until it has:

1. A bounded purpose.
2. A named evidence owner.
3. A named consequence owner.
4. A named external stop authority.
5. A rejection condition.
6. A reversible test procedure.
7. A ledger event specification.
8. A specialist handoff route.
9. An uncertainty register.
10. A statement of what the packet does not claim.

## Current omissions

- The ledger is not yet persistent or independently custody-verified.
- The external brake is declared and locally checked, not physically validated.
- Owner IDs are not proof of actual authority.
- Revocation timing is not yet measured across cached, queued, delegated, or replicated access.
- Specialist handoff is tested as a packet, not yet as a complete disposition loop.
- The 51-50 method is documented but not yet a reusable compiler.
- Full-suite status remains 43/45 because two Zombie Permission Hunter expiry fixtures are stale.

## Stop condition

If evidence, owner, denial authority, reversibility, or external stop path is missing, the packet remains PREPARATION ONLY and routes to specialist review.

Passing preparation tests does not establish safety, compliance, authority, deployment readiness, or publication approval.

**Only Green proceeds. Green is eligibility for bounded human review, not permission.**
