# Repository maintenance optimization | bounded implementation
Date: 2026-10-29 | State: DEVELOPMENT CANDIDATE / NOT MERGED
Owner: human BoundaryTitan owner. This branch is maintenance-only. No production deployment, automatic merge, publication, deletion of evidence, or change to frozen doctrine.

## Priority and evidence
P0: state/manifest integrity; missing checks; workflow and evidence continuity; branch enforcement remains separately unverified. P1: branch lifecycle and review queue. P2: consequence dependency graph and cross-domain failure transfer as later candidate projects.

## What this branch adds
- A read-only **offline integrity sentinel** that inventories tracked paths and checks current manifest coverage, byte hashes, duplicate paths, and selected workflow evidence controls. It does not repair, authorize or certify.
- Deterministic negative-control fixtures and tests, including missing manifest entry, modified file, duplicate entry, and absent workflow.
- A machine-readable maintenance queue and branch lifecycle policy.
- An explicit review gate: no promotion until independently reproduced on a clean checkout with preserved command logs.

## Maintenance cadence (proposed; not scheduled)
Per PR: verify state, typecheck, tests, dependency audit, workflow permission diff, and relevant claim receipts.
Daily: detect missed scheduled checks, CI failure, dependency alerts and changed authority surfaces. Requires external run-history collector, NOT IMPLEMENTED.
Weekly: branch inventory, review backlog, orphaned records, duplicate candidate research.
Monthly: specialist outcome reconciliation, official-source freshness and revision snapshots.
Quarterly: independent challenge of checker absence, shared custodians, restart and stop path.

## Current limits
This implementation is intentionally local/offline. It cannot prove GitHub branch protection, CI execution, workflow scheduling, delivery acknowledgments, independent custody, or that all consequential paths have been enumerated. It does not auto-edit manifests. Unknown is not pass. Missing-run detection requires an independent provider-side run ledger, and is **NOT IMPLEMENTED** here.

## Required promotion receipts
Record exact base/head SHA; `python3 -m unittest discover -s maintenance/tests -v`; `python3 maintenance/integrity_sentinel.py --root .`; `npm ci`; `npm run verify:state`; `npm run typecheck`; `npm test`; `npm run test:python`; `npm audit --omit=dev`. Preserve raw outputs, exit codes, dependency snapshot, failed-run receipts, and external reviewer objections. A failure of the current manifest after adding these files is expected until the branch's tracked-tree manifest is regenerated by the repository's own approved process; do not quietly overwrite the ledger.
